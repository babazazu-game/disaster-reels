## Что сохранить без изменений (это API, им пользуется src/game.ts)
`new Reels(parent, stopLabel)`, `spin(onDone, forced)`, `hide()`, `get spinning`, `press()`, `update(dt)` (игра зовёт каждый кадр, пока барабан открыт; мир при этом стоит на паузе), поле `open`, тип `ReelResult`. Логика: СТОП жмут ТРИ раза — каждое нажатие останавливает следующую ленту; жёлтый счётчик оставшихся нажатий на кнопке; следующая лента подсвечена; без нажатий AUTO_STOP=5 с — ленты встают сами с шагом AUTO_GAP; `forced` подменяет итог ленты в момент её остановки; клавиши E/Enter; после третьей остановки `onDone(r)` и через ~1,4 с барабан прячется. Атлас иконок `assets/reel.webp?v=${__BUILD__}`, `ICON`, `iconPos` — как есть. Подписей под иконками НЕ показывать (решение заказчика): лента 0 — крупные числа, ленты 1 и 2 — только иконки.

## Что сделать

1. **Анимация как в казино.** Сейчас картинки просто подменяются на месте — заказчику не нравится. Нужно: каждая лента — окно, в котором крутится вертикальный барабан-цилиндр с символами по кругу (числа / иконки свойств / иконки существ, в порядке списков COUNTS / ADJ_IDS / NOUN_IDS).
   - Символы едут сверху вниз непрерывно, быстро (~12–16 символов в секунду), видно центральный символ целиком и края соседних сверху и снизу.
   - Объём цилиндра: сверху и снизу окна тёмный градиент (символ «уходит за край»), блик-полоса по центру, символы у краёв чуть сжаты по вертикали/темнее (можно просто градиентной маской поверх — дёшево). Во время быстрого вращения — лёгкое размытие по вертикали (например filter: blur(1px) на ленте или вытянутость), при остановке — чётко.
   - Остановка: лента НЕ встаёт мгновенно — замедляется ~0,4–0,5 с и доезжает ровно до целевого символа с небольшим перелётом и отскоком назад (ease-out-back), затем короткий «щелчок» (scale), как сейчас `.reel.done`.
   - Двигать только через `transform: translateY(...)` (и, если нужно, перестановку 5–7 переиспользуемых элементов — виртуальная лента), без пересоздания DOM каждый кадр и без чтения layout каждый кадр. Анимация ведётся из `update(dt)` (не CSS-анимацией и не requestAnimationFrame отдельно), чтобы её можно было гонять в автотесте.
   - Ленты стартуют с разных случайных позиций, у каждой чуть своя скорость.
2. **Положение.** На телефоне (`@media (pointer:coarse)`) барабан по ЦЕНТРУ экрана по вертикали (чуть выше центра), потому что внизу кнопки управления (прыжок) и барабан их закрывает. На компьютере — внизу по центру, как сейчас. Размеры адаптивные (портрет и альбом), кнопка СТОП справа от лент, крупная (≥56 px).
3. **Исчезновение.** Сейчас на телефоне барабан после выбора НЕ исчезает: прячется сдвигом `translate(-50%,140%)`, а при `bottom:24vh` этого мало. Прятать надёжно: opacity 0 + scale ~0.85 + `visibility:hidden` (после перехода) + `pointer-events:none`; показ — «выпрыгивание» (scale с лёгким перелётом). Проверь, что после `hide()` ничего не перекрывает экран и кнопки под ним нажимаются.
4. Стиль оставить как сейчас (красная рамка, белая кайма, жёлтая внутренняя линия, кремовые ленты, шрифт Rubik 900, пульсирующая кнопка СТОП) — только ленты стали цилиндрами.

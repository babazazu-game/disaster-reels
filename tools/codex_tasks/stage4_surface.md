## Что сделать

1. `export const enum Cell { None = 0, Fire = 1, Ice = 2, Wet = 3, Shock = 4, Slime = 5 }`
2. `export type ReactionId = 'steam' | 'melt' | 'shock' | 'slimeFire';`
3. Конструктор: `constructor(scene, half, flames: Flames, bolts: Flames)` — `bolts` это тот же класс Flames с текстурой жёлтой молнии (аддитивный), его `add(x, y, z, size, seed)` рисует молнию на кадр. Существующий `flames` остаётся.
4. Публичное поле `onReact: ((id: ReactionId, x: number, z: number) => void) | null = null` — зовётся при реакции с координатами центра клетки. Не чаще одного вызова на клетку за действие.
5. Таймеры: огонь — как сейчас (BURN), лёд — постоянный (как сейчас), `WET = 12` с → None, `SHOCK = 1.6` с → снова Wet с таймером WET, `SLIME = 10` с → None.
6. Правила (это и есть реакции):
   - `ignite(x, z, time)`: на Ice → клетка становится Wet (лёд растаял), onReact('melt'); на Wet → огонь гаснет, клетка остаётся Wet (таймер обновить), onReact('steam'); на Slime → Fire со временем time*2 (слизь горит дольше), onReact('slimeFire'); на Shock — ничего; иначе как сейчас.
   - `freeze(k)` / `freezeAt(x, z)`: Fire → Wet (лёд потушил огонь, лужа), onReact('steam'), вернуть true; Wet/Slime/Shock/None → Ice. Сигнатуры сохранить.
   - новый `wetAt(x, z)`: None/Slime → Wet; Fire → Wet + onReact('steam'); Ice — без изменений; Wet/Shock — обновить таймер.
   - новый `shockAt(x, z): number`: если клетка Wet или Shock — заливкой по 4 соседям пройти ВСЕ связанные Wet/Shock клетки (не больше 80), сделать их Shock с таймером SHOCK; вернуть число клеток; если >0 и среди них были не-Shock — onReact('shock') один раз. Иначе 0.
   - новый `slimeAt(x, z)`: None/Wet → Slime (таймер SLIME); Slime — обновить таймер; остальное без изменений.
   - `at(x, z)` как есть.
   - новый `counts(): { fire: number; ice: number; wet: number; shock: number; slime: number }` — для автотеста.
   - `reset()` чистит всё.
7. Отрисовка (бюджет: +3 вызова отрисовки максимум, т.е. по одному InstancedMesh на Wet, Slime, Shock; пересборка экземпляров только когда `dirty`, как сейчас):
   - Wet — лужа: canvas-текстура (голубая полупрозрачная вода, 2–3 светлых кольца-ряби, мягкий край, чтобы соседние лужи сливались), MeshStandardMaterial roughness ~0.05, transparent, polygonOffset как у льда, высота y≈0.035, плоскость чуть крупнее клетки (STEP*1.15).
   - Slime — ярко-зелёная глянцевая слизь с пузырями (canvas), y≈0.045, тоже чуть крупнее клетки.
   - Shock — как лужа, но жёлто-белая/ярко-голубая (выглядит «под током»), y≈0.05; КАЖДЫЙ кадр в `update` рисовать молнии через `bolts.add` над клетками под током: на клетку 1 молния в случайной точке клетки на высоте 0.2–0.6, размер 0.9–1.4, но всего не больше 40 за кадр (если клеток много — случайная выборка). Мерцание достаточно через случайность.
   - Огонь и лёд — как сейчас. Не забудь сбрасывать `dummy.rotation`/`scale` перед `updateMatrix` (общий dummy с градом — уже есть комментарий).
   - Все новые InstancedMesh: `frustumCulled = false`, `receiveShadow = true`, `count = 0` на старте, размер буфера = total клеток.
8. Обнови шапочный комментарий файла (бюджет вызовов) и комментарий у `ignite` («Лёд огонь НЕ берёт — сначала он должен растаять (этап 4)» больше не верен).

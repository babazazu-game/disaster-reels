## 1. Экран персонажей — `src/game/characters.ts`

```ts
export interface CharState { coins: number; owned: string[]; selected: string; adViews: Record<string, number> }
export class Characters {
  constructor(parent: HTMLElement, L: (ru: string, en: string) => string);
  onSelect?: (id: string) => void;              // нажали на открытого персонажа — выбрать
  onBuy?: (id: string) => void;                 // купить за монеты (хватает монет)
  onAd?: (id: string) => Promise<void>;         // посмотреть ролик за этого персонажа (игра сама считает просмотры и обновит show())
  onClose?: () => void;                         // назад в меню (кнопка «назад» и Esc)
  show(s: CharState): void;                     // открыть или перерисовать с новым состоянием
  hide(): void;
  get open(): boolean;
}
```
- Полноэкранный оверлей поверх меню (z-index выше `.mnu-*`, например 30), лёгкая вуаль, как у меню. Классы с префиксом `chr-`, один `<style>`.
- Сверху: заголовок на ленте «ПЕРСОНАЖИ» / «CHARACTERS», слева круглая кнопка «назад» (стрелка), справа плашка монет: иконка `assets/ui/icons/coin.webp?v=${__BUILD__}` (fallback — жёлтый кружок CSS) и число.
- Сетка карточек всех `ROSTER` (11 шт.): портрет `assets/chars/<id>.webp?v=${__BUILD__}` (квадрат, прозрачный фон; если не загрузился — силуэт/первая буква), имя `L(c.ru, c.en)` под портретом.
  - выбранный: золотая обводка + зелёная галочка в углу (как карточка сложности в меню);
  - открытый, не выбранный: обычная карточка, по нажатию `onSelect(id)`;
  - закрытый: портрет затемнён/силуэтом, замочек; снизу ДВЕ маленькие кнопки: «💰 цена» (иконка coin + число; неактивна и приглушена, если монет не хватает; по нажатию `onBuy`) и «▶ N/M» (иконка `assets/ui/icons/ad.webp`, fallback ▶; N — сколько роликов уже просмотрено `adViews[id] ?? 0`, M — `c.ads`; по нажатию `onAd(id)`; пока промис не завершён — кнопка в состоянии ожидания, повторно не жмётся). Если `c.ads === 0` — кнопку рекламы не показывать.
- Короткая анимация «открыт!» (выпрыгивание карточки), когда персонаж в новом `show()` стал открытым, а раньше не был.
- Должно помещаться: портрет 360×640 (сетка 3 колонки, вертикальная прокрутка ВНУТРИ сетки разрешена, шапка закреплена), альбом 640×360 (4–6 колонок), десктоп 1920×1080 (6 колонок, сетка не шире ~1100px, по центру). Кнопки ≥44 px по меньшей стороне (кнопки цены/рекламы могут быть 36–40 px высотой, но шириной во всю карточку пополам). Длинные имена не рвутся посреди слова.
- Скрытие — как в menu.ts (opacity + visibility + inert + pointer-events:none). Esc = onClose. Клики — `click` (installTap уже ставит menu).

## 2. Правки `src/game/menu.ts`
- Кнопка ПЕРСОНАЖИ сейчас с иконкой `people` (группа людей) — заказчик принимает её за «сетевую игру». Заменить: на кнопке — портрет ТЕКУЩЕГО персонажа `assets/chars/<id>.webp` (fallback — иконка `person`), а «Скоро!» (`mnu-soon`, `soonTimer`, `clearSoon`) убрать вовсе; по нажатию просто `onCharacters()`.
- Плашка монет в главном меню (в верхнем левом углу с учётом safe-area, тот же вид, что в экране персонажей).
- API меняется так (игра будет звать именно так):
  - `showMain(d: Difficulty, muted: boolean, coins: number, skin: string): void`
  - `setCoins(n: number): void` — обновить число монет везде, где оно видно (с коротким «подпрыгиванием» числа, если выросло).
  - `ResultInfo` получает поля `coins: number` (заработано за раунд) и `total: number` (всего после начисления).
  - На экране итога — строка «+N 💰» (иконка coin), число набегает от 0 до N за ~0,6 с; рядом/под ней кнопка «×2 ▶» (иконка ad) — вызывает `onDouble?: () => Promise<boolean>`; пока ждём — кнопка в ожидании; если вернулось true — число становится 2N с праздничным подпрыгиванием, кнопка исчезает; если false — кнопка снова активна. Если `coins === 0` — кнопку ×2 не показывать.
  - Остальное API (`onPlay`, `onRetry`, `onMenu`, `onResume`, `onPause`, `onMute`, `onCharacters`, `showPause`, `hide`, `open`, `setPauseButton`) — не менять.
- Всё по-прежнему помещается без прокрутки в 360×640, 640×360, 1920×1080, тексты не вылезают (проверь и английский).

## Требования
- Никаких внешних библиотек/картинок, кроме перечисленных `assets/...` (их кладёт другой разработчик; на момент твоей работы их может не быть — fallback обязателен, ничего не должно ломаться).
- Без `backdrop-filter` и тяжёлых `filter: blur` на больших площадях.
- Для самопроверки можно временно создать демо-HTML в корне (vite dev уже запущен на http://localhost:5210, можно открыть /твой-демо.html) — в конце удалить.

В итоговом ответе — кратко, что сделано и точное итоговое API.
